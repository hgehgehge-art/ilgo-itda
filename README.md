# 읽고, 잇다 — 해외문학회의 읽기와 대화를 잇는 웹사이트

기준일: 2026년 10월 20일. 서버는 **구글 시트 하나**입니다. 시트에 붙은 Apps Script가 세미나 신청·대출 상태·토론 기록·독서 지도를 처리하고, 사이트(GitHub Pages)는 그 주소 하나만 부릅니다. Apps Script를 배포하기 전에는 세미나 일정 조회, 토론 기록 파일 만들기, 독서 지도 보기가 서버 없이 동작합니다. 정확한 확인 범위는 [6. 검증 기록](#6-검증-기록)에 있습니다.

## 1. 목적과 서비스 배경

저는 한국외대 중앙동아리 해외문학회 회장이고, Social Science & AI 융합학부 24학번입니다. AX·DX 전환에 관심이 있어, 동아리를 운영하며 손으로 하던 일을 웹으로 옮겨 보고 싶었습니다.

| 운영 일 | 지금까지 | 불편한 점 | 이 사이트에서 |
| --- | --- | --- | --- |
| 세미나 참석 | 카카오톡 투표를 회장이 세어 마감 | 동아리방에 11명까지만 앉을 수 있어 정원을 꼭 지켜야 하는데, 사람이 일일이 확인 | 이름·확인번호로 선착순 신청·취소, 11명이 차면 자동 마감 |
| 도서 대출 | 종이 장부 | 장부 앞에 가야 빌릴 수 있는지 앎 | 책장에서 검색하고 대출 가능 여부·반납 예정일 확인 |
| 세미나 대화 | 끝나면 남지 않음 | 한 학기 동안 무엇을 이야기했는지 흩어짐 | 그날의 키워드·질문을 '그날의 토론'으로 기록 |
| 책 읽는 장소 | 각자 네이버 지도에 저장 | 동아리가 아끼는 곳을 함께 볼 수 없음 | '독서 지도'에 모으고 회원이 추천 |

사이트에 들를 때마다 읽을거리가 있도록 매일 바뀌는 '오늘의 한 문장'도 넣었습니다.

## 2. 주요 사용자

**세미나에 참석하려는 해외문학회 회원**입니다. 회원 가입 없이 이용합니다. 핵심 흐름은 **세미나 찾기 → 이름·확인번호로 신청 → 인원 확인 → (필요하면) 같은 이름·확인번호로 취소**입니다. 운영진은 구글 시트에서 일정·대출·장소를 관리하고, 토론 기록은 운영진 코드로 올립니다.

## 4. 사용·실행·수정 방법

**회원이 세미나 신청하기:** 세미나 화면에서 '접수 중'인 카드의 '신청하기' → 이름과 확인번호 4자리(숫자) → '신청'. 인원이 바로 늘어납니다. 취소는 같은 카드의 '신청 취소'에 같은 이름·확인번호를 넣습니다. 확인번호를 잊으면 운영진에게 요청합니다.

**운영진이 토론 기록 올리기:** 토론 화면 아래 '토론 기록 만들기'에서 세미나를 고르고 받아쓰기 텍스트를 붙여 넣은 뒤 '키워드 뽑기' → 필요 없는 낱말은 눌러서 빼기 → 요약·질문을 다듬고 운영진 코드로 '초안 저장' 또는 '게시'. 'AI 정리 요청'을 켜면 30분 안에 Claude가 요약·질문 초안을 채우고, 운영진이 확인한 뒤 게시합니다.

**회원이 장소 추천하기:** 독서 지도 아래 '좋아하는 곳 추천하기'에 이름·주소·분류·이유를 적고 확인란을 체크해 보냅니다. 운영진이 시트에서 '게시'로 바꾸면 지도에 '회원 추천'으로 올라갑니다.

### 처음 설정(운영진, 한 번)

1. 구글 드라이브에서 새 스프레드시트 「읽고, 잇다 운영 (비공개)」를 만듭니다. 링크 공유는 켜지 않습니다.
2. 확장 프로그램 → Apps Script에 `apps-script/Code.gs`를 붙여 넣고 저장합니다.
3. 스프레드시트를 새로 고치면 위쪽에 **'읽고, 잇다'** 메뉴가 생깁니다. ① 처음 설정(탭 만들기) ② 세미나 시트 연결(주간세미나 시트 주소 붙여 넣기) ③ 운영진 코드 정하기를 차례로 실행합니다. 처음 실행 때 권한 허용 창이 뜹니다.
4. Apps Script 편집기에서 배포 → 새 배포 → 유형 '웹 앱', 실행 사용자 '나', 액세스 권한 '모든 사용자' → 배포. 나온 `…/exec` 주소를 `assets/js/config.js`의 `APPS_SCRIPT_URL`에 넣고 올립니다.
5. `도서 목록` 탭에는 `sheets/book-list-draft.csv`(민음사 공식 목록 484종)를 파일 → 가져오기로 넣고, 실물과 대조해 고칩니다.
6. (선택) AI 정리: 메뉴의 'AI 작업 토큰 만들기'로 받은 토큰과 웹 앱 주소, Claude API 키를 GitHub Secrets의 `AI_WORKER_TOKEN`, `APPS_SCRIPT_URL`, `ANTHROPIC_API_KEY`에 등록합니다.

운영 시트의 탭: `세미나 신청`(신청자 명단. 대리 취소는 '취소 시각' 칸에 시각을 적음) · `도서 목록` · `대출 기록`(빌려줄 때 한 줄, 반납받으면 실제 반납일) · `토론 기록` · `독서 지도`(회원 추천은 '검토 대기' → 운영진이 '게시'로 바꿈. 위도·경도는 비워 두면 주소로 자동 채움).

### 내 컴퓨터에서 실행

Node.js 20 이상에서 저장소 폴더를 열고 실행한 뒤 http://localhost:8000 을 엽니다. `APPS_SCRIPT_URL`이 비어 있으면 가짜 응답으로 신청·토론 저장을 시험할 수 있습니다(토론 운영진 코드는 `local-test`).

```sh
node scripts/serve.mjs
```

## 7. 알려진 한계

- 이름과 확인번호는 엄밀한 본인 인증이 아닙니다. 다른 사람 이름으로 신청하는 것을 막지 못해 운영진이 명단을 확인합니다. 확인번호가 4자리라 여러 번 시도하면 맞힐 수 있습니다.
- Apps Script는 응답이 1~3초 걸릴 수 있고, 구글 계정의 하루 사용량 한도가 있습니다. 동아리 규모에서는 충분합니다.
- 서버가 응답하지 않으면 세미나 일정은 공개 시트를 직접 읽어 보여 주지만, 이때는 신청을 받지 않습니다. 주간세미나 시트는 '링크가 있는 모든 사용자' 공유라, 원본에서는 발제자 이름이 보입니다.
- 토론 키워드는 단어 빈도 규칙이라 형태소 분석만큼 정확하지 않습니다. AI 정리는 사람이 확인해야 게시됩니다.
- 네이버 지도 개인 저장 목록은 가져오는 공개 API가 없어, 운영진이 시트에 옮겨 적습니다.
- 대출 시트에 실제 기록을 넣기 전까지 책장의 대출 상태는 예시입니다.
