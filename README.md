# 읽고, 잇다 — 해외문학회 책장과 세미나 신청

> 기준일 2026년 10월 4일. 공개 홈페이지에서 **세미나 참석 신청**과 **책장 조회**, **오늘의 한 문장**을 제공합니다. 세미나 일정은 동아리의 「26-2 주간세미나」 구글 시트를 그대로 읽어 보여 주며, 시트를 고치면 몇 분 안에 사이트에 반영됩니다. 대출 시트는 아직 만들지 않아, 책장은 민음사 공식 목록에 예시 대출 상태를 붙여 보여 줍니다. 자세한 상태는 [4. 현재 상태](#4-현재-상태)에 있습니다.

## 1. 목적

저는 한국외대 중앙 동아리 해외문학회 회장이고, Social Science & AI 융합학부 24학번입니다. AX·DX 전환에 관심이 많아, 동아리를 운영하면서 손으로 하던 일을 웹으로 옮겨 보고 싶었습니다. **읽고, 잇다**는 해외문학회의 **책장 대출 상태 조회**와 **주간 세미나 참석 신청**을 웹으로 옮긴 사이트이자, 2026-2 기술개발연구프로젝트의 개인 홈페이지 과제입니다.

**방문자:** 해외문학회 회원(세미나 신청, 책 찾기)과 운영진(일정·대출 관리), 그리고 저를 소개받는 사람(제작자 소개·작업 기록).

- 공개 홈페이지: https://hgehgehge-art.github.io/ilgo-itda/
- 로그인 없이 누구나 열 수 있고, 휴대전화에서도 같은 화면으로 쓸 수 있습니다.

### 서비스 배경

해외문학회는 민음사 세계문학전집 전체를 소장하고, 매주 오후 6시 동아리방에서 발제 세미나를 엽니다. 이 두 가지를 운영하는 방식에 각각 불편이 있었습니다.

| 운영 일 | 지금까지의 방식 | 불편한 점 | 이 사이트에서 바뀌는 점 |
| --- | --- | --- | --- |
| 도서 대출 | 대출·반납을 **종이 장부**에 기록 | 장부가 있는 곳에서만 볼 수 있어, 어떤 책을 지금 빌릴 수 있는지 회원이 미리 알기 어려움 | 운영진은 비공개 시트에 기록하고, 회원은 웹 **책장**에서 책을 검색해 대출 가능 여부와 반납 예정일을 확인 |
| 세미나 참석 | **카카오톡 투표**로 참석자를 받고 회장이 직접 인원을 세어 마감 | 정원(발제자 포함 11명)이 찼는지 사람이 확인해야 하고, 마감과 취소 반영이 회장의 수작업에 달려 있음 | 회원이 웹에서 이름과 확인번호로 **선착순 신청·취소**하고, 정원이 차면 서버가 자동으로 마감 |

운영 방식은 동아리 규모에 맞게 가볍게 정했습니다.

- **운영진이 새로 배울 것이 없게:** 일정과 대출은 지금처럼 구글 시트에 적습니다. 사이트가 시트를 직접 읽어 가므로, 운영진은 사이트를 따로 고치지 않습니다.
- **회원 가입 없이:** 로그인을 만들지 않고, 세미나 신청은 이름과 본인이 정한 확인번호 4자리로 합니다.
- **이름은 공개하지 않게:** 빌린 회원과 신청자의 이름은 사이트와 공개 저장소 어디에도 내보내지 않습니다.

**1. 세미나 신청**

- 동아리의 「26-2 주간세미나」 시트에 발제 날짜와 작품이 적히면 사이트에 세미나 카드가 생깁니다. '작가 - 작품'은 '작가 『작품』'으로 보여 줍니다.
- 다가오는 세미나를 날짜순으로 보여 주고, 지난 세미나는 아래에 따로 모읍니다.
- 카드마다 날짜와 시간(한국시간), 장소, 작품, 발제자(가려서 표시), 신청 인원과 막대, 상태(접수 중 / 마감 / 종료 / 취소), 시트의 비고를 표시합니다.
- **신청:** 이름과 확인번호 4자리를 입력합니다. 확인번호 칸은 숫자만 받으며, 취소할 때 필요하다는 안내를 함께 보여 줍니다.
- **취소:** 신청 때와 같은 이름과 확인번호를 입력합니다. 이름이 없을 때와 확인번호가 틀릴 때 같은 문구를 보여 줘, 누가 신청했는지 알아낼 수 없습니다.
- 결과는 신청 완료 / 이미 신청함 / 정원 마감 / 이미 시작한 세미나 / 확인번호 불일치 / 일시적 오류 중 하나로 알려 주고, 곧바로 인원을 다시 불러옵니다.
- 정원은 발제자를 포함한 11명이라, 회원 10명이 신청하면 11/11로 마감됩니다. 취소로 자리가 나면 다시 열립니다.
- 여러 명이 마지막 한 자리에 동시에 신청해도 한 명만 성공합니다.

**2. 책장**

- 소장한 전집을 한 권씩 카드로 보여 줍니다. 카드에는 권번호, 제목, 작가·번역자, 관리번호, 대출 상태가 나옵니다.
- **대출 가능**은 남색 표시, **대출 중**은 회색 표시와 함께 "10월 11일 반납 예정"처럼 반납 예정일을 보여 줍니다.
- "데미안"(제목), "헤세"(작가), "44" 또는 "44권"(권번호)으로 찾을 수 있습니다. 띄어쓰기는 구분하지 않습니다.
- 500권 가까운 목록을 한꺼번에 그리지 않고 30권씩 보여 주며, '더 보기'로 이어서 봅니다.
- 같은 책을 두 권 소장하면 관리번호로 구분해 각각 표시합니다.
- 마지막으로 시트를 읽은 시각과 "대출 상태는 시트를 고친 뒤 몇 분 늦게 반영될 수 있습니다"를 함께 표시합니다.

**3. 오늘의 한 문장**

- 하루에 한 번 GitHub Actions가 한국어 명언 API에서 문장을 받아 저장하므로, 같은 날에는 모든 방문자가 같은 문장을 봅니다.
- 카드에는 문장, 말한 사람, 인물 소개, 날짜, 출처 링크가 나옵니다. '홈페이지 둘러보기', 닫기 버튼, Esc 키로 닫습니다.
- 한 번 닫으면 그날은 같은 브라우저에서 다시 자동으로 열리지 않고, 상단 배너의 '다시 읽기'로 언제든 다시 엽니다.
- 문장 갱신이 실패해 어제 문장이 남아 있으면 '오늘의'라고 부르지 않고 날짜를 붙여 보여 줍니다.

**4. 구글 시트 연동**

- 운영진은 사이트를 고치지 않고 Google Sheets만 수정합니다. 신청 서버(Supabase)가 시트를 읽어 사이트에 넘겨주므로, 별도 프로그램이나 동기화 작업이 없습니다.
- **세미나:** 「26-2 주간세미나」 시트를 형식 그대로 읽습니다. 휴회 기간처럼 날짜가 하루가 아닌 행과 작품이 비어 있는 행은 건너뜁니다. 시간·장소·정원은 오후 6시·동아리방·11명입니다.
- **대출:** 대출 기록 탭에 한 줄을 추가하면 '대출 중', 실제 반납일을 채우면 '대출 가능'이 됩니다. 도서 목록 탭의 수식이 상태를 계산하며, 회원 이름이 있는 대출 기록 탭은 공개하지 않습니다.
- 사이트는 마지막으로 읽은 내용을 바로 보여 주고, 시트를 다시 읽어 바뀐 것이 있으면 화면을 고칩니다. 신청·취소할 때는 항상 최신 일정으로 확인합니다.

**공통**

- 디자인은 넉넉한 여백과 큰 제목, 강조색 하나를 쓰는 애플 웹사이트의 분위기를 참고했습니다. 강조색은 해외문학회 로고의 남색이고, 홈 첫 화면에는 로고의 '기울어 이어지는 책' 모양을 그렸습니다.
- 키보드로 쓸 수 있도록 만들고 초점 표시를 넣었습니다. 문장 카드와 세미나 신청 양식의 초점 이동은 확인했고, 전체 페이지 키보드 점검은 아직입니다. 화면 움직임을 줄이는 설정에서는 등장 효과를 빼도록 했습니다(직접 확인은 아직).
- 데이터를 읽지 못하면 빈 화면 대신 "정보를 불러오지 못했습니다"를 보여 줍니다.

여기서 **예약은 세미나 참석 예약**을 뜻합니다. 도서 예약은 없습니다.

### 첫 버전에 넣지 않는 것

- 로그인·회원가입, 회원별 마이페이지(본인 대출 내역 조회 포함)
- 사이트 안의 운영진 관리 화면
- 도서 예약, 대기자 자동 승계
- AI 챗봇, 리뷰·댓글·추천 기능
- 부원이 문장을 직접 고르거나 등록하는 기능

### 로그인 없이 운영하는 방식

| 하는 일 | 누가 | 어디서 | 본인·권한 확인 |
| --- | --- | --- | --- |
| 책장·일정·오늘의 한 문장 보기 | 누구나 | 홈페이지 | 없음 |
| 세미나 신청 | 회원 | 홈페이지 | 이름 + 본인이 정한 확인번호 4자리 |
| 세미나 신청 취소 | 신청한 회원 | 홈페이지 | 신청 때 입력한 이름·확인번호 일치 |
| 신청자 명단 확인 | 운영진 | 데이터 저장소 관리 화면 | 저장소 계정(운영진만 보유) |
| 대출·반납 기록 | 운영진 | 비공개 Google Sheets | 시트 편집 권한(운영진만 보유) |
| 세미나 일정 등록·수정 | 운영진 | 주간세미나 Google Sheets | 시트 편집 권한 |

운영진 권한은 사이트의 로그인이 아니라 **Google Sheets와 데이터 저장소의 기존 계정 권한**으로 구분합니다.

**이 방식의 한계**

- 이름과 확인번호는 엄밀한 본인 인증이 아닙니다. 다른 사람 이름으로 신청하는 것을 기술적으로 막지 못하므로, 운영진이 마감 후 명단을 확인합니다.
- 확인번호가 4자리 숫자라, 여러 번 시도하면 남의 신청을 취소할 수 있습니다. 동아리 규모를 고려해 시도 횟수 제한은 두지 않았습니다.
- 확인번호를 잊으면 직접 취소할 수 없고, 운영진에게 요청해야 합니다.
- 회원은 사이트에서 자신의 대출 내역을 따로 조회할 수 없습니다. 책별 대출 상태만 확인합니다.
- 시트를 고친 내용은 몇 분 늦게 반영될 수 있습니다(구글의 내보내기 지연과 서버의 1분 저장 간격).
- 세미나 카드의 발제자 이름은 첫 글자만 보이게 가립니다(예: 홍○○). 신청자 이름은 아예 보여 주지 않습니다.

### 도서 데이터: 민음사 세계문학전집

해외문학회는 **민음사 세계문학전집 전체를 소장하고 있습니다.** 소장한 전집 전체를 도서 데이터베이스에 등록하고, 이후 새로 출간된 권은 동아리가 들여놓은 뒤에 추가합니다.

- **소장 범위:** `[실물 확인 후 첫 권번호~마지막 권번호와 총 권수 입력]`

전집의 권번호·제목·작가·번역자는 [민음사 공식 홈페이지의 세계문학전집 시리즈 목록](https://minumsa.minumsa.com/book_series/world-literatures/)을 기준으로 합니다. 공식 목록에 실린 484종(1~502권 중 목록에 있는 권)을 `sheets/book-list-draft.csv`로 정리해 두었고, 책장의 실물과 한 권씩 대조해 빠진 권이나 중복 소장본을 표시합니다.

- **도서 정보(공개):** 전집 권번호, 제목, 작가, 번역자, ISBN.
- **소장본 정보(공개):** 실물 책마다 부여하는 관리번호, 연결된 도서 정보, 대출 가능 여부, 반납 예정일.
- **대출 기록(비공개 시트):** 소장본 관리번호, 빌린 회원 이름, 대출일, 반납 예정일, 실제 반납일.

같은 제목을 두 권 소장하면 관리번호도 두 개를 부여합니다. 전집 권번호나 ISBN만으로 실물 책을 구분하지 않습니다.

대출·반납은 운영진이 실물 책을 확인하고 비공개 시트에 한 줄씩 기록하며, 이전 대출 이력은 지우지 않습니다. **빌린 회원의 이름은 사이트와 공개 GitHub 저장소로 내보내지 않습니다.** 한 소장본에 반납되지 않은 대출이 두 건 이상이면 도서 목록의 상태 칸에 '확인 필요'가 뜨고, 사이트에는 '대출 중'으로 보입니다.

전집 소장은 완료되었으며, 대출 시트 등록은 준비 중입니다. 대출 시트를 연결하기 전까지 책장은 공식 목록에 예시 관리번호와 예시 대출 상태를 붙여 보여 주고, 화면에 그 사실을 안내합니다. 초기 등록 시 기존 수기 대출 기록과 현재 책의 위치를 대조해 각 책의 대출·반납 상태를 반영합니다.

### 세미나 예약 규칙

- 신청할 때 이름과 확인번호 4자리를 입력합니다. 확인번호는 본인이 정하며, 취소할 때 다시 입력합니다.
- 같은 세미나에 같은 이름으로는 한 번만 신청할 수 있습니다. 동명이인은 이름 뒤에 구분 표기를 붙이도록 안내합니다.
- 세미나는 **오후 6시에 동아리방**에서 엽니다.
- 정원은 **발제자를 포함해 11명**입니다. 발제자는 따로 신청하지 않고 한 자리를 차지하므로, 회원이 신청할 수 있는 자리는 10석입니다. 사이트의 신청 인원에는 발제자가 포함됩니다(신청 전 1/11).
- 신청은 **선착순**입니다. 별도 마감일 없이 시트에 일정이 적히면 바로 받고, 정원이 차거나 세미나가 시작하면 닫습니다.
- 여러 회원이 동시에 신청해도 확정 인원이 11명을 넘지 않도록, 서버의 데이터 저장 단계에서 정원 확인과 신청 확정을 함께 처리합니다.
- 세미나가 시작했거나 정원이 찬 경우 신청을 받지 않습니다. 취소도 세미나 시작 전까지만 할 수 있습니다.
- 사이트에는 **신청 인원 수만** 표시합니다. 신청자 이름은 공개하지 않고 운영진만 확인합니다.

### 오늘의 한 문장

문장은 부원이 고르지 않고 **[한국어 명언 API](https://github.com/gwongibeom/korean-advice-open-api)**에서 받아 옵니다. 가입이나 인증키 없이 호출할 수 있는 공개 API입니다.

| 항목 | 내용 |
| --- | --- |
| 호출 주소 | `GET https://korean-advice-open-api.vercel.app/api/advice` |
| 응답 | `message`(문장), `author`(말한 사람), `authorProfile`(인물 소개) |
| 동작 | 호출할 때마다 무작위 문장 하나를 돌려줌. 날짜·조건 지정 불가 |
| 이용 조건 | 자체 라이선스. 상업적으로 쓸 때는 제작자에게 문의해야 함 |

홈페이지가 방문할 때마다 API를 직접 부르면 사람마다 다른 문장이 나옵니다. 그래서 **GitHub Actions가 하루에 한 번만 호출해 결과를 `data/today-quote.json`에 저장**하고, 홈페이지는 이 파일만 읽습니다. 같은 날짜에는 모두 같은 문장을 보고, API가 잠시 멈춰도 사이트에는 마지막으로 받은 문장이 남습니다.

**이 방식의 한계**

- 이 API가 주는 것은 작가·화가·정치인 등의 **명언**이며, 문학 작품 속 문장만 나오지 않습니다. 작품명·번역자·쪽수 정보도 없습니다.
- 한국어로 된 문학 작품 문장만 제공하는 공개 API는 찾지 못했습니다. 책 속 문장을 주는 Recite API(영어)는 응답을 직접 확인하지 못해 연결하지 않았습니다.
- 문장의 정확성과 출처는 API 제공 데이터에 의존하며, 직접 검증하지 않습니다.
- 개인이 운영하는 무료 API여서 예고 없이 중단되거나 응답 형식이 바뀔 수 있습니다.

**이용 흐름**

1. 그날 처음 홈페이지에 접속하면 화면 가운데 문장 카드가 부드럽게 나타납니다.
2. 회원은 문장과 출처를 읽고 '홈페이지 둘러보기' 또는 닫기 버튼으로 카드를 닫습니다.
3. 카드를 닫으면 바로 책장이나 세미나 예약을 이용할 수 있습니다. 문장은 사이트 상단의 작은 배너로 남습니다.
4. 배너의 '다시 읽기'를 누르면 문장 카드를 다시 볼 수 있습니다.
5. 다음 한국 날짜가 되면 새로운 문장을 표시합니다.

'하루 첫 방문'은 **같은 기기·브라우저 기준**으로 판단합니다. 한 번 닫은 카드는 그날 메뉴를 이동하거나 새로고침해도 자동으로 다시 열지 않습니다. 다른 브라우저를 사용하거나 브라우저에 저장된 사이트 데이터를 삭제하면 다시 나타날 수 있습니다. 문장 저장·댓글 기능과 AI로 문장을 생성하는 기능은 첫 버전에 포함하지 않습니다.

### 신청 서버의 접근 제한

로그인이 없으므로 홈페이지는 누구나 쓸 수 있는 공개 키로 서버에 접속합니다. 그래서 서버 쪽에서 다음과 같이 제한합니다.

- 홈페이지는 신청 기록 표를 직접 읽거나 쓸 수 없고, **신청·취소·인원 조회·시트 읽기용 서버 함수만** 호출합니다.
- 시트 주소는 서버에만 저장되어 있어, 서버가 다른 주소를 읽게 만들 수 없습니다. 시트에서도 정해진 열만 꺼내 씁니다.
- 신청 함수는 세미나 시작 전인지, 중복 여부, 남은 자리를 한 번에 확인하고 저장합니다.
- 취소 함수는 이름과 확인번호가 일치하는 신청만 취소합니다.
- 인원 조회 함수는 세미나별 신청 인원 수만 돌려줍니다. 이름과 확인번호는 돌려주지 않습니다.
- 확인번호는 원문 그대로 저장하지 않고 솔트를 넣은 해시로 저장합니다.
- 관리용 비밀키는 프런트엔드 코드와 공개 저장소에 넣지 않습니다.

### 구글 시트: 세미나

서버가 「26-2 해외문학회 주간세미나」 시트의 첫 탭(`시트1`)을 CSV로 읽습니다. 운영진이 쓰던 형식을 그대로 쓰며, 원본 시트는 고치지 않습니다.

| 시트 열 | 사이트에서 |
| --- | --- |
| 주차 (기간) | 쓰지 않음 |
| 발제 날짜 (월/일 요일) | 세미나 날짜. 연도는 오늘 기준 앞뒤 6개월 안으로 정함. 시간은 오후 6시 |
| 작가 및 작품명 | 카드 제목. '작가 - 작품' → '작가 『작품』' |
| 발제자 | 카드의 '발제' 표시(첫 글자만 보이게 가림) |
| 비고 | 카드의 안내 문구 |

- **세미나 ID**는 날짜로 만듭니다(예: `2026-10-07`). 행 순서를 바꿔도 같은 세미나로 봅니다. 날짜를 바꾸면 새 세미나가 되며, 이전 날짜의 신청 기록은 지우지 않고 서버에 남습니다(운영진이 관리 화면에서 확인).
- 날짜가 하루가 아닌 행(`10/12 ~ 10/19` 같은 휴회 기간)과 작품이 빈 행은 건너뜁니다. 작품이 적혀 있으면 신청을 받습니다.
- 장소·정원·발제문 링크를 따로 쓰고 싶으면 `세미나 ID`·`개최 일시`·`장소`·`정원`·`게시 상태`(초안/게시/취소)·`발제문 URL`·`공개 안내` 열이 있는 정리된 형식도 읽습니다.
- 시트를 읽지 못하면(공유 해제 등) 서버는 마지막으로 읽은 일정을 계속 씁니다.
- Google Docs는 발제문을 여는 링크로만 연결합니다. 문서 본문을 자동 분석해 일정을 추출하는 기능은 포함하지 않습니다.

### 구글 시트: 대출

대출 시트는 운영진만 볼 수 있는 비공개 스프레드시트입니다.

| 탭 | 열 | 공개 여부 |
| --- | --- | --- |
| 도서 목록 | 관리번호, 전집 권번호, 제목, 작가, 번역자, ISBN, 상태(수식), 반납 예정일(수식) | 이 탭만 '웹에 게시' |
| 대출 기록 | 관리번호, 빌린 회원 이름, 대출일, 반납 예정일, 실제 반납일 | 비공개 |

1. 운영진이 책을 빌려줄 때 대출 기록에 한 줄을 추가하고, 반납받으면 그 줄의 실제 반납일을 채웁니다.
2. 도서 목록의 '상태'·'반납 예정일' 열은 수식이 대출 기록을 보고 계산합니다. 회원 이름은 계산에 쓰지 않습니다.
3. 도서 목록 탭만 '웹에 게시'하고, 서버가 그 주소를 읽습니다.

### 오늘의 한 문장 갱신

| 파일 | 역할 |
| --- | --- |
| `scripts/update-quote.mjs` | 명언 API를 호출해 문장을 검증하고 `data/today-quote.json`에 저장 |
| `.github/workflows/daily-quote.yml` | 매일 스크립트를 실행하고, 파일이 바뀌면 저장소에 커밋 |
| `data/today-quote.json` | 홈페이지의 첫 방문 카드와 상단 배너가 읽는 데이터 |

저장되는 데이터의 형태는 다음과 같습니다.

```json
{
  "date": "2026-10-04",
  "message": "위대한 일은 작은 일들의 축적으로 이루어진다.",
  "author": "빈센트 반 고흐",
  "authorProfile": "네덜란드 화가",
  "source": {
    "name": "한국어 명언 API",
    "url": "https://github.com/gwongibeom/korean-advice-open-api"
  },
  "fetchedAt": "2026-10-04T11:06:25.755Z"
}
```

**동작 규칙**

1. 워크플로는 매일 한국시간 0시 5분에 예약 실행되며, Actions 화면에서 수동으로도 실행할 수 있습니다.
2. 스크립트는 한국 날짜를 기준으로 합니다. 저장된 파일의 날짜가 오늘이면 API를 호출하지 않고 끝냅니다. 같은 날 다시 실행해도 문장이 바뀌지 않습니다.
3. 날짜가 바뀌었으면 API를 호출합니다. 문장이 비었거나 300자를 넘거나 직전 문장과 같으면 다시 받으며, 최대 4번 시도합니다.
4. 4번 모두 실패하면 파일을 건드리지 않고 오류로 끝냅니다. 사이트에는 마지막으로 받은 문장과 그 날짜가 그대로 남고, Actions 실행 기록에 실패가 표시됩니다.
5. 수동 실행에서 `force`를 켜면 오늘 문장이 이미 있어도 새 문장으로 바꿉니다. 부적절한 문장이 나왔을 때 사용합니다.
6. 워크플로가 올린 커밋으로 GitHub Pages가 자동으로 다시 배포됩니다(2026-10-04 확인).

**주의할 점**

- GitHub Actions의 예약 실행은 지연될 수 있으므로 정확히 자정에 변경된다고 보장하지 않습니다.

### 설정 방법

**신청 서버(Supabase)** — 2026-10-04 아래 1~4단계를 실제로 진행해 확인했습니다. 5단계는 아직 해 보지 않았습니다. 새 키 형식(`sb_publishable_…`, `sb_secret_…`)과 예전 형식(`anon`, `service_role`) 모두 쓸 수 있습니다.

1. Supabase에서 프로젝트를 만듭니다. 사용자 계정(Auth) 기능은 쓰지 않습니다.
2. 관리 화면 → SQL Editor에서 `supabase/schema.sql`, 이어서 `supabase/sheets.sql`을 실행합니다.
3. Project Settings → API Keys의 Project URL과 공개용 키(Publishable key)를 `assets/js/config.js`에 넣습니다. 관리용 키(Secret key)는 어디에도 넣지 않습니다.
4. 점검: SQL Editor에서 `supabase/test-seminars.sql`의 [준비] 부분을 실행한 뒤, 아래 명령을 실행합니다. 끝나면 같은 파일의 [정리] 부분을 실행합니다.

   ```bash
   SUPABASE_URL=https://프로젝트.supabase.co SUPABASE_ANON_KEY=공개용키 node scripts/check-supabase.mjs
   ```

5. 신청자 명단은 관리 화면 → Table Editor → `reservations`에서 봅니다. 대리 취소는 해당 행의 `cancelled_at`에 현재 시각을 넣습니다(행은 지우지 않습니다).

**구글 시트 연결** — 시트 주소를 서버의 `sheet_sources` 표에 등록합니다. 세미나(1번)는 2026-10-04 연결해 사이트에 실제 일정이 나오는 것을 확인했습니다. 대출(2~4번)은 아직 해 보지 않았습니다.

1. **세미나:** 주간세미나 시트가 '링크가 있는 모든 사용자 보기'로 공유되어 있으면 SQL Editor에서 아래처럼 등록합니다(첫 탭을 읽음. 다른 탭이면 주소 끝에 `&gid=탭번호`).

   ```sql
   insert into public.sheet_sources (kind, csv_url) values
     ('seminars', 'https://docs.google.com/spreadsheets/d/<시트 ID>/export?format=csv')
   on conflict (kind) do update set csv_url = excluded.csv_url;
   ```

2. **대출 시트 만들기:** 새 스프레드시트에 `도서 목록`, `대출 기록` 탭을 만들고 위 표의 열 이름을 1행에 적습니다. 도서 목록에는 `sheets/book-list-draft.csv`를 파일 → 가져오기로 넣을 수 있습니다. **이 스프레드시트는 링크 공유를 켜지 않습니다.**
3. **상태 수식:** 도서 목록의 G1, H1 칸에 아래 수식을 넣으면 아래 행이 자동으로 채워집니다(대출 기록 열 순서: A 관리번호, B 빌린 회원 이름, C 대출일, D 반납 예정일, E 실제 반납일). 아직 실제 시트에서 확인하지 않은 수식입니다.

   ```
   G1: ={"상태"; ARRAYFORMULA(IF(A2:A="",, IF(COUNTIFS('대출 기록'!A:A, A2:A, '대출 기록'!E:E, "")>1, "확인 필요", IF(COUNTIFS('대출 기록'!A:A, A2:A, '대출 기록'!E:E, "")=1, "대출 중", "대출 가능"))))}
   H1: ={"반납 예정일"; ARRAYFORMULA(IF(G2:G="대출 중", IFERROR(VLOOKUP(A2:A&"|", {'대출 기록'!A:A&"|"&'대출 기록'!E:E, '대출 기록'!D:D}, 2, FALSE)),))}
   ```

4. **도서 목록만 웹에 게시:** 파일 → 공유 → 웹에 게시 → '도서 목록' 탭, 'CSV' → 게시. 나온 주소를 `('books', '<주소>')`로 1번처럼 등록합니다.

- 등록한 주소는 서버에만 있고 사이트 코드에는 없습니다. 바꾸려면 같은 `insert … on conflict` 문을 다시 실행합니다.
- 주소를 등록하지 않은 동안에는 사이트가 예시 데이터(`data/*.json`)를 보여 줍니다. 등록했지만 한 번도 읽지 못했으면 "정보를 불러오지 못했습니다"를 보여 줍니다.
