# 읽고, 잇다 — 해외문학회 대출 기록과 세미나 예약

> 기준일 2026년 10월 4일. 홈페이지(홈·책장·세미나·오늘의 한 문장)를 구현해 GitHub Pages로 공개했고, 세미나 신청 저장소(Supabase)와 오늘의 한 문장 자동 갱신을 연결해 점검했습니다. **Google Sheets 연동은 아직 연결하지 못해** 책장과 세미나 일정은 화면 확인용 예시 데이터로 보여 주며, 예시 일정에는 신청을 받지 않습니다. 자세한 상태는 [4. 현재 상태](#4-현재-상태)에 있습니다.

## 1. 서비스 소개

**읽고, 잇다**는 한국외대 중앙 동아리 해외문학회의 **책장 대출 상태 조회**와 **주간 세미나 참석 신청**을 웹으로 옮긴 사이트입니다. 해외문학회 회장인 제작자가 동아리를 운영하며 겪은 문제를 고치려고 만든 개인 프로젝트이자, 대학 과제(개인 홈페이지)입니다.

- 공개 홈페이지: https://hgehgehge-art.github.io/ilgo-itda/
- 로그인 없이 누구나 열 수 있고, 휴대전화에서도 같은 화면으로 쓸 수 있습니다.

### 서비스 배경

해외문학회는 민음사 세계문학전집 전체를 소장하고, 매주 오후 6시 동아리방에서 발제 세미나를 엽니다. 이 두 가지를 운영하는 방식에 각각 불편이 있었습니다.

| 운영 일 | 지금까지의 방식 | 불편한 점 | 이 사이트에서 바뀌는 점 |
| --- | --- | --- | --- |
| 도서 대출 | 대출·반납을 **종이 장부**에 기록 | 장부가 있는 곳에서만 볼 수 있어, 어떤 책을 지금 빌릴 수 있는지 회원이 미리 알기 어려움 | 운영진은 비공개 시트에 기록하고, 회원은 웹 **책장**에서 책을 검색해 대출 가능 여부와 반납 예정일을 확인 |
| 세미나 참석 | **카카오톡 투표**로 참석자를 받고 회장이 직접 인원을 세어 마감 | 정원(발제자 포함 11명)이 찼는지 사람이 확인해야 하고, 마감과 취소 반영이 회장의 수작업에 달려 있음 | 회원이 웹에서 이름과 확인번호로 **선착순 신청·취소**하고, 정원이 차면 서버가 자동으로 마감 |

운영 방식은 동아리 규모에 맞게 가볍게 정했습니다. 회원 가입과 로그인을 만들지 않고, 운영진은 이미 쓰고 있는 Google Sheets와 데이터 저장소 관리 화면의 계정 권한으로 일합니다. 빌린 회원과 신청자의 이름은 사이트와 공개 저장소 어디에도 내보내지 않습니다.

### 기능 소개

| 화면 | 기능 | 상태 |
| --- | --- | --- |
| [홈](https://hgehgehge-art.github.io/ilgo-itda/) | 동아리와 서비스 소개, 프로젝트 목적과 현재 상태, 제작자 소개·관심 분야, GitHub 작업 기록 링크 | 공개 |
| 모든 화면 상단 | **오늘의 한 문장**: 그날 첫 방문에 문장 카드가 열리고, 닫으면 상단 배너로 남음 | 공개, 매일 자동 갱신 |
| [책장](https://hgehgehge-art.github.io/ilgo-itda/books.html) | 민음사 세계문학전집을 제목·작가·권번호로 검색, 대출 가능한 책만 보기, 대출 중인 책의 반납 예정일 표시 | 공개. 책 정보는 공식 목록 기준, 대출 상태는 예시 |
| [세미나](https://hgehgehge-art.github.io/ilgo-itda/seminars.html) | 세미나 일정과 신청 인원(예: 7/11) 확인, 이름·확인번호 4자리로 참석 신청과 취소 | 신청 서버 연결·점검 완료. 일정은 예시라 신청은 아직 받지 않음 |
| 운영(사이트 밖) | Google Sheets에 적은 세미나 일정과 대출 기록을 30분마다 사이트에 반영 | 스크립트 작성·점검 완료, 시트 미연결 |

**1. 책장**

- 소장한 전집을 한 권씩 카드로 보여 줍니다. 카드에는 권번호, 제목, 작가·번역자, 관리번호, 대출 상태가 나옵니다.
- **대출 가능**은 남색 표시, **대출 중**은 회색 표시와 함께 "10월 11일 반납 예정"처럼 반납 예정일을 보여 줍니다.
- "데미안"(제목), "헤세"(작가), "44" 또는 "44권"(권번호)으로 찾을 수 있습니다. 띄어쓰기는 구분하지 않습니다.
- 500권 가까운 목록을 한꺼번에 그리지 않고 30권씩 보여 주며, '더 보기'로 이어서 봅니다.
- 같은 책을 두 권 소장하면 관리번호로 구분해 각각 표시합니다.
- 마지막 동기화 시각과 "대출 상태는 최대 30분 늦게 반영될 수 있습니다"를 함께 표시합니다.

**2. 세미나 신청**

- 다가오는 세미나를 날짜순으로 보여 주고, 지난 세미나는 아래에 따로 모읍니다.
- 카드마다 날짜와 시간(한국시간), 장소, 작품, 발제자, 신청 인원과 막대, 상태(접수 중 / 마감 / 종료 / 취소)를 표시합니다.
- **신청:** 이름과 확인번호 4자리를 입력합니다. 확인번호 칸은 숫자만 받으며, 취소할 때 필요하다는 안내를 함께 보여 줍니다.
- **취소:** 신청 때와 같은 이름과 확인번호를 입력합니다. 이름이 없을 때와 확인번호가 틀릴 때 같은 문구를 보여 줘, 누가 신청했는지 알아낼 수 없습니다.
- 결과는 신청 완료 / 이미 신청함 / 정원 마감 / 이미 시작한 세미나 / 확인번호 불일치 / 일시적 오류 중 하나로 알려 주고, 곧바로 인원을 다시 불러옵니다.
- 정원은 발제자를 포함한 11명이라, 회원 10명이 신청하면 11/11로 마감됩니다. 취소로 자리가 나면 다시 열립니다.
- 여러 명이 마지막 한 자리에 동시에 신청해도 한 명만 성공합니다. 실제 서버에서 5명 동시 신청으로 확인했습니다.

**3. 오늘의 한 문장**

- 하루에 한 번 GitHub Actions가 한국어 명언 API에서 문장을 받아 저장하므로, 같은 날에는 모든 방문자가 같은 문장을 봅니다.
- 카드에는 문장, 말한 사람, 인물 소개, 날짜, 출처 링크가 나옵니다. '홈페이지 둘러보기', 닫기 버튼, Esc 키로 닫습니다.
- 한 번 닫으면 그날은 같은 브라우저에서 다시 자동으로 열리지 않고, 상단 배너의 '다시 읽기'로 언제든 다시 엽니다.
- 문장 갱신이 실패해 어제 문장이 남아 있으면 '오늘의'라고 부르지 않고 날짜를 붙여 보여 줍니다.

**4. 운영 자동화**

- 운영진은 사이트를 고치지 않고 Google Sheets만 수정합니다. 세미나는 게시 상태를 '게시'로 바꾸면 사이트에 나타나고, '취소'로 바꾸면 취소로 표시됩니다.
- 대출은 대출 기록 시트에 한 줄을 추가하면 '대출 중', 실제 반납일을 채우면 '대출 가능'이 됩니다.
- 한 책에 반납되지 않은 대출이 두 건이면 기록 실수로 보고 그 책의 상태를 바꾸지 않으며, 실행 기록에 오류로 남깁니다.

**공통**

- 디자인은 넉넉한 여백과 큰 제목, 강조색 하나를 쓰는 애플 웹사이트의 분위기를 참고했습니다. 강조색은 해외문학회 로고의 남색이고, 홈 첫 화면에는 로고의 '기울어 이어지는 책' 모양을 그렸습니다.
- 키보드로 쓸 수 있도록 만들고 초점 표시를 넣었습니다. 문장 카드와 세미나 신청 양식의 초점 이동은 확인했고, 전체 페이지 키보드 점검은 아직입니다. 화면 움직임을 줄이는 설정에서는 등장 효과를 빼도록 했습니다(직접 확인은 아직).
- 데이터를 읽지 못하면 빈 화면 대신 "정보를 불러오지 못했습니다"를 보여 줍니다.

여기서 **예약은 세미나 참석 예약**을 뜻합니다. 도서 예약은 없습니다.

### 첫 버전에 넣지 않는 것

- 로그인·회원가입, 회원별 마이페이지(본인 대출 내역 조회 포함)
- 사이트 안의 운영진 관리 화면
- 도서 예약, 대기자 자동 승계
- AI 챗봇, 리뷰·댓글·추천 기능
- 부원이 문장을 직접 고르거나 등록하는 기능

정원이 차면 신청을 막고, 세미나 시작 전 취소로 자리가 생기면 다시 신청할 수 있게 합니다.

### 로그인 없이 운영하는 방식

| 하는 일 | 누가 | 어디서 | 본인·권한 확인 |
| --- | --- | --- | --- |
| 책장·일정·오늘의 한 문장 보기 | 누구나 | 홈페이지 | 없음 |
| 세미나 신청 | 회원 | 홈페이지 | 이름 + 본인이 정한 확인번호 4자리 |
| 세미나 신청 취소 | 신청한 회원 | 홈페이지 | 신청 때 입력한 이름·확인번호 일치 |
| 신청자 명단 확인 | 운영진 | 데이터 저장소 관리 화면 | 저장소 계정(운영진만 보유) |
| 대출·반납 기록 | 운영진 | 비공개 Google Sheets | 시트 편집 권한(운영진만 보유) |
| 세미나 일정 등록·수정 | 운영진 | Google Sheets | 시트 편집 권한 |

운영진 권한은 사이트의 로그인이 아니라 **Google Sheets와 데이터 저장소의 기존 계정 권한**으로 구분합니다.

**이 방식의 한계**

- 이름과 확인번호는 엄밀한 본인 인증이 아닙니다. 다른 사람 이름으로 신청하는 것을 기술적으로 막지 못하므로, 운영진이 마감 후 명단을 확인합니다.
- 확인번호를 잊으면 직접 취소할 수 없고, 운영진에게 요청해야 합니다.
- 회원은 사이트에서 자신의 대출 내역을 따로 조회할 수 없습니다. 책별 대출 상태만 확인합니다.
- 대출 상태는 시트 동기화 주기만큼 늦게 반영될 수 있습니다.

### 도서 데이터: 민음사 세계문학전집

해외문학회는 **민음사 세계문학전집 전체를 소장하고 있습니다.** 소장한 전집 전체를 도서 데이터베이스에 등록하고, 이후 새로 출간된 권은 동아리가 들여놓은 뒤에 추가합니다.

- **소장 범위:** `[실물 확인 후 첫 권번호~마지막 권번호와 총 권수 입력]`

전집의 권번호·제목·작가·번역자는 [민음사 공식 홈페이지의 세계문학전집 시리즈 목록](https://minumsa.minumsa.com/book_series/world-literatures/)에서 확인할 수 있습니다. 내려받을 수 있는 공식 목록 파일은 확인하지 못했으므로, 공식 목록을 기준으로 표를 만들고 책장의 실물과 한 권씩 대조해 빠진 권이나 중복 소장본을 표시합니다.

- **도서 정보(공개):** 전집 권번호, 제목, 작가, 번역자, ISBN.
- **소장본 정보(공개):** 실물 책마다 부여하는 관리번호, 연결된 도서 정보, 대출 가능 여부, 반납 예정일.
- **대출 기록(비공개 시트):** 소장본 관리번호, 빌린 회원 이름, 대출일, 반납 예정일, 실제 반납일.

같은 제목을 두 권 소장하면 관리번호도 두 개를 부여합니다. 전집 권번호나 ISBN만으로 실물 책을 구분하지 않습니다.

대출·반납은 운영진이 실물 책을 확인하고 비공개 시트에 한 줄씩 기록하며, 이전 대출 이력은 지우지 않습니다. **빌린 회원의 이름은 사이트와 공개 GitHub 저장소로 내보내지 않습니다.** 동기화 스크립트는 한 소장본에 반납되지 않은 대출이 두 건 이상이면 오류로 처리하고, 해당 책의 상태를 갱신하지 않습니다.

전집 소장은 완료되었으며, 도서 데이터베이스 등록은 준비 중입니다. 지금 사이트의 책장은 공식 목록에서 가져온 484종(1~502권 중 목록에 있는 권)을 보여 주며, 관리번호와 대출 상태는 예시입니다. 초기 등록 시 기존 수기 대출 기록과 현재 책의 위치를 대조해 각 책의 대출·반납 상태를 반영합니다.

### 세미나 예약 규칙

- 신청할 때 이름과 확인번호 4자리를 입력합니다. 확인번호는 본인이 정하며, 취소할 때 다시 입력합니다.
- 같은 세미나에 같은 이름으로는 한 번만 신청할 수 있습니다. 동명이인은 이름 뒤에 구분 표기를 붙이도록 안내합니다.
- 세미나는 **오후 6시에 동아리방**에서 엽니다.
- 정원은 **발제자를 포함해 11명**입니다. 발제자는 따로 신청하지 않고 한 자리를 차지하므로, 회원이 신청할 수 있는 자리는 10석입니다. 사이트의 신청 인원에는 발제자가 포함됩니다(신청 전 1/11).
- 신청은 **선착순**입니다. 별도 마감일 없이 일정이 게시되면 바로 받고, 정원이 차거나 세미나가 시작하면 닫습니다.
- 여러 회원이 동시에 신청해도 확정 인원이 11명을 넘지 않도록, 서버의 데이터 저장 단계에서 정원 확인과 신청 확정을 함께 처리합니다.
- 세미나가 시작했거나 정원이 찬 경우 신청을 받지 않습니다. 취소도 세미나 시작 전까지만 할 수 있습니다.
- 사이트에는 **신청 인원 수만** 표시합니다. 신청자 이름은 공개하지 않고 운영진만 확인합니다.

### 오늘의 한 문장

문장은 부원이 고르지 않고 **[한국어 명언 API](https://github.com/gwongibeom/korean-advice-open-api)**에서 받아 옵니다. 가입이나 인증키 없이 호출할 수 있는 공개 API입니다.

| 항목 | 내용 |
| --- | --- |
| 호출 주소 | `GET https://korean-advice-open-api.vercel.app/api/advice` |
| 응답 | `message`(문장), `author`(말한 사람), `authorProfile`(인물 소개) |
| 동작 | 호출할 때마다 무작위 문장 하나를 돌려줌. 날짜·조건 지정 불가 |
| 이용 조건 | 자체 라이선스. 상업적으로 쓸 때는 제작자에게 문의해야 함 |

홈페이지가 방문할 때마다 API를 직접 부르면 사람마다 다른 문장이 나옵니다. 그래서 **GitHub Actions가 하루에 한 번만 호출해 결과를 `data/today-quote.json`에 저장**하고, 홈페이지는 이 파일만 읽습니다. 같은 날짜에는 모두 같은 문장을 보고, API가 잠시 멈춰도 사이트에는 마지막으로 받은 문장이 남습니다.

화면에는 문장과 함께 말한 사람, 인물 소개, 출처(한국어 명언 API)를 표시합니다.

**이 방식의 한계**

- 이 API가 주는 것은 작가·화가·정치인 등의 **명언**이며, 문학 작품 속 문장만 나오지 않습니다. 작품명·번역자·쪽수 정보도 없습니다.
- 한국어로 된 문학 작품 문장만 제공하는 공개 API는 찾지 못했습니다. 책 속 문장을 주는 Recite API(영어)는 응답을 직접 확인하지 못해 연결하지 않았습니다.
- 문장의 정확성과 출처는 API 제공 데이터에 의존하며, 직접 검증하지 않습니다.
- 개인이 운영하는 무료 API여서 예고 없이 중단되거나 응답 형식이 바뀔 수 있습니다.

**이용 흐름**

1. 그날 처음 홈페이지에 접속하면 화면 가운데 문장 카드가 부드럽게 나타납니다.
2. 회원은 문장과 출처를 읽고 '홈페이지 둘러보기' 또는 닫기 버튼으로 카드를 닫습니다.
3. 카드를 닫으면 바로 책장이나 세미나 예약을 이용할 수 있습니다. 문장은 사이트 상단의 작은 배너로 남습니다.
4. 배너의 '다시 읽기'를 누르면 문장 카드를 다시 볼 수 있습니다.
5. 다음 한국 날짜가 되면 새로운 문장을 표시합니다.

'하루 첫 방문'은 **같은 기기·브라우저 기준**으로 판단합니다. 한 번 닫은 카드는 그날 메뉴를 이동하거나 새로고침해도 자동으로 다시 열지 않습니다. 다른 브라우저를 사용하거나 브라우저에 저장된 사이트 데이터를 삭제하면 다시 나타날 수 있습니다.

카드는 키보드와 닫기 버튼으로 닫을 수 있도록 하고, 닫은 뒤 페이지를 계속 탐색할 수 있도록 초점을 관리합니다. 화면 움직임을 줄이는 설정에서는 등장 효과를 생략합니다. 문장 저장·댓글 기능과 AI로 문장을 생성하는 기능은 첫 버전에 포함하지 않습니다.

## 3. 실행·수정 방법

### 구성

실제로 구현한 구성은 다음과 같습니다.

| 구성 요소 | 역할 |
| --- | --- |
| 홈페이지·GitHub Pages | 개인 소개, 책장, 세미나 신청 화면, 오늘의 한 문장 카드·배너 제공 |
| 예약 데이터 저장소(Supabase) | 세미나 신청 기록 보관, 정원·중복 처리. 홈페이지는 서버 함수 세 개만 호출. 사용자 계정 기능은 쓰지 않음. 연결 완료 |
| Google Sheets(일정) | 운영진이 세미나 일정을 작성하는 원본. 동기화 미연결 |
| Google Sheets(대출, 비공개) | 운영진이 대출·반납을 기록하는 원본. 시트 미생성·동기화 미연결 |
| 한국어 명언 API | 오늘의 한 문장의 원본. Actions만 호출하고 홈페이지는 직접 호출하지 않음 |
| GitHub Actions | 명언 API 호출과 문장 갱신(작동 중), 일정·대출 상태 동기화(작성했으나 꺼 둠). 배포는 Pages가 커밋마다 자동으로 함 |

세미나 신청·취소는 사용자가 누르는 즉시 예약 데이터 저장소에 기록하며, 다음 Actions 실행을 기다리지 않습니다. 도서 대출 상태와 세미나 일정은 Actions 동기화 주기에 맞춰 갱신합니다.

### 예약 데이터 저장소의 접근 제한

로그인이 없으므로 홈페이지는 누구나 쓸 수 있는 공개 키로 저장소에 접속합니다. 그래서 저장소 쪽에서 다음과 같이 제한합니다.

- 홈페이지는 신청 기록 표를 직접 읽거나 쓸 수 없고, **신청·취소·인원 조회용 서버 함수만** 호출합니다.
- 신청 함수는 세미나 시작 전인지, 중복 여부, 남은 자리를 한 번에 확인하고 저장합니다.
- 취소 함수는 이름과 확인번호가 일치하는 신청만 취소합니다.
- 인원 조회 함수는 세미나별 신청 인원 수만 돌려줍니다. 이름과 확인번호는 돌려주지 않습니다.
- 확인번호는 원문 그대로 저장하지 않습니다.
- 관리용 비밀키는 프런트엔드 코드와 공개 저장소에 넣지 않습니다.

### Google Sheets에서 세미나 가져오기

공유받은 「26-2 해외문학회 주간세미나」의 `시트1`에서 다음 구조를 확인했습니다.

| 기존 항목 | 홈페이지에서 사용할 내용 |
| --- | --- |
| 주차(기간) | 주차별 묶음 |
| 발제 날짜 | 세미나 날짜 |
| 작가 및 작품명 | 세미나 카드 제목·책 정보 |
| 발제자 | 발제자 표시 |
| 비고 | 공개할 안내 사항을 선별하여 표시 |

연동할 때는 아래 필드를 보완할 계획입니다. 기존 시트에 필요한 열을 추가하거나 별도의 사이트 연동용 표로 관리하는 방식은 운영진과 정합니다.

- **세미나 ID:** 행을 이동하거나 날짜를 수정해도 바뀌지 않는 고유값.
- **개최 일시:** 연도를 포함한 날짜. 시작 시간은 적지 않으면 오후 6시(한국시간)로 처리.
- **장소:** 적지 않으면 동아리방.
- **정원:** 기본값 11명(발제자 포함).
- **게시 상태:** 초안 / 게시 / 취소.
- **발제문 URL:** Google Docs 등 발제 자료 링크. 선택 항목.

등록 흐름은 `시트에 일정 작성 → 게시 상태 확인 → 정기 동기화 → 세미나 신청 카드 생성·수정`입니다. 자동화 스크립트는 제목·날짜 등 필수값이 없는 행을 게시하지 않습니다. 신청 시작·마감 일시는 따로 두지 않습니다.

동기화는 **30분 간격과 수동 실행을 지원하는 방식**을 우선 검토합니다. 같은 세미나 ID는 기존 일정만 수정하고, 예약 기록은 유지합니다. 행이 사라졌다고 기존 예약을 자동 삭제하지 않으며, 취소는 게시 상태로 명시합니다. 일정이 바뀌면 사이트에서 변경 사실을 확인할 수 있게 합니다.

Google Docs는 첫 버전에서 발제문을 여는 링크로만 연결합니다. 문서 본문을 자동 분석해 일정을 추출하는 기능은 포함하지 않습니다.

### Google Sheets에서 대출 상태 가져오기

대출 시트는 운영진만 볼 수 있는 비공개 시트로 새로 만듭니다.

| 시트 | 열 | 공개 여부 |
| --- | --- | --- |
| 도서 목록 | 관리번호, 전집 권번호, 제목, 작가, 번역자, ISBN | 공개 |
| 대출 기록 | 관리번호, 빌린 회원 이름, 대출일, 반납 예정일, 실제 반납일 | 비공개 |

1. 운영진이 책을 빌려줄 때 대출 기록에 한 줄을 추가하고, 반납받으면 그 줄의 실제 반납일을 채웁니다.
2. Actions가 세미나 일정과 같은 주기로 두 시트를 읽습니다.
3. 실제 반납일이 빈 기록이 있는 소장본은 '대출 중', 없으면 '대출 가능'으로 계산합니다.
4. 사이트에는 도서 목록과 계산한 상태, 반납 예정일만 내보냅니다. 회원 이름은 내보내지 않습니다.

Actions가 비공개 시트를 읽는 데 필요한 인증 정보는 GitHub 저장소의 비밀 설정에 보관하고, 코드에 적지 않습니다.

### GitHub Actions로 '오늘의 한 문장' 갱신

이 부분은 파일을 작성했습니다.

| 파일 | 역할 |
| --- | --- |
| `scripts/update-quote.mjs` | 명언 API를 호출해 문장을 검증하고 `data/today-quote.json`에 저장 |
| `.github/workflows/daily-quote.yml` | 매일 스크립트를 실행하고, 파일이 바뀌면 저장소에 커밋 |
| `data/today-quote.json` | 홈페이지의 첫 방문 카드와 상단 배너가 읽는 데이터. 첫 실행 때 생성 |

저장되는 데이터의 형태는 다음과 같습니다.

```json
{
  "date": "2026-10-04",
  "message": "위대한 일은 작은 일들의 축적으로 이루어진다.",
  "author": "빈센트 반 고흐",
  "authorProfile": "네덜란드 화가",
  "source": {
    "name": "한국어 명언 API",
    "url": "https://github.com/gwongibeom/korean-advice-open-api"
  },
  "fetchedAt": "2026-10-04T11:06:25.755Z"
}
```

**동작 규칙**

1. 워크플로는 매일 한국시간 0시 5분에 예약 실행되며, Actions 화면에서 수동으로도 실행할 수 있습니다.
2. 스크립트는 한국 날짜를 기준으로 합니다. 저장된 파일의 날짜가 오늘이면 API를 호출하지 않고 끝냅니다. 같은 날 다시 실행해도 문장이 바뀌지 않습니다.
3. 날짜가 바뀌었으면 API를 호출합니다. 문장이 비었거나 300자를 넘거나 직전 문장과 같으면 다시 받으며, 최대 4번 시도합니다.
4. 4번 모두 실패하면 파일을 건드리지 않고 오류로 끝냅니다. 사이트에는 마지막으로 받은 문장과 그 날짜가 그대로 남고, Actions 실행 기록에 실패가 표시됩니다.
5. 수동 실행에서 `force`를 켜면 오늘 문장이 이미 있어도 새 문장으로 바꿉니다. 부적절한 문장이 나왔을 때 사용합니다.

**직접 실행하기**

Node.js 18 이상이 필요하며, 설치할 패키지는 없습니다. 저장소 최상위 폴더에서 실행합니다.

```bash
node scripts/update-quote.mjs             # 오늘 문장이 없으면 받아서 저장
FORCE=true node scripts/update-quote.mjs  # 오늘 문장이 있어도 교체
```

**주의할 점**

- GitHub Actions의 예약 실행은 지연될 수 있으므로 정확히 자정에 변경된다고 보장하지 않습니다.
- 공개 저장소에서 60일 동안 저장소 활동이 없으면 예약 실행이 비활성화될 수 있어, 운영 중 실행 기록을 확인합니다.
- 워크플로가 저장소에 커밋하려면 저장소 설정에서 Actions의 쓰기 권한이 허용되어 있어야 합니다.
- 배포 방식은 GitHub Pages의 브랜치 배포(main, 최상위 폴더)입니다. 2026-10-04에 Actions가 올린 커밋(오늘의 한 문장 force 실행)으로 Pages가 자동으로 다시 배포되어 공개 주소에 새 문장이 반영되는 것을 확인했습니다. 그래서 워크플로에 별도 배포 단계를 넣지 않았습니다.

### 실행 안내

- **필요한 프로그램·설치 명령:** 문장 갱신 스크립트는 Node.js 18 이상. 홈페이지는 빌드 도구 없는 HTML·CSS·JavaScript이며, 로컬 미리보기에도 Node.js만 필요합니다(설치할 패키지 없음)
- **로컬 실행 명령·접속 주소:** 저장소 최상위 폴더에서 `node scripts/serve.mjs` 실행 후 http://localhost:8000 접속. 파일을 더블클릭해 `file://`로 열면 데이터 파일을 읽지 못합니다
- **설정 방법 — 세미나 신청 저장소(Supabase):** 2026-10-04 아래 1~4단계를 실제로 진행해 확인했습니다. 5단계(명단 확인·대리 취소)는 아직 해 보지 않았습니다. Supabase의 새 키 형식(`sb_publishable_…`, `sb_secret_…`)과 예전 형식(`anon`, `service_role`) 모두 쓸 수 있습니다.
  1. Supabase에서 프로젝트를 만듭니다. 사용자 계정(Auth) 기능은 쓰지 않습니다.
  2. 관리 화면 → SQL Editor에 `supabase/schema.sql` 전체를 붙여 넣고 실행합니다.
  3. Project Settings → API에서 Project URL과 공개용 키(anon public)를 `assets/js/config.js`에 넣습니다. 관리용 키(service_role)는 여기에 넣지 않고 GitHub 저장소의 Secrets에만 `SUPABASE_SERVICE_ROLE_KEY`로 등록합니다.
  4. 점검: SQL Editor에서 `supabase/test-seminars.sql`의 [준비] 부분을 실행한 뒤, 저장소 최상위 폴더에서 `SUPABASE_URL=… SUPABASE_ANON_KEY=… node scripts/check-supabase.mjs`를 실행합니다. 끝나면 같은 파일의 [정리] 부분을 실행합니다.
  5. 신청자 명단은 관리 화면 → Table Editor → `reservations`에서 봅니다. 대리 취소는 해당 행의 `cancelled_at`에 현재 시각을 넣습니다(행은 지우지 않습니다).
